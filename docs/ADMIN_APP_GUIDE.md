# دليل تطوير تطبيق TRINEX Admin

## الهدف والنطاق
تطبيق إدارة Flutter مستقل. تغييرات هذا المستودع تخص تطبيق الإدارة، ولا تعني نشر الموقع العام أو تعديل خدمة API. يجب تنفيذ أي تغيير بالخادم كمهمة منفصلة وبموافقة صريحة.

## قرارات واجهة المستخدم الحالية
- العربية هي اللغة الوحيدة في الواجهة، واتجاه التخطيط RTL.
- الثيم يتبع إعداد النظام تلقائيًا عبر `themeMode: ThemeMode.system`، مع تعريف ثيم فاتح وداكن متكافئين.
- مكونات التصميم المشتركة موجودة في `lib/src/design_system/`.
- حقول التاريخ والوقت المرئية تستخدم `AdminDateTimeField`؛ اختيار الوقت بنظام 12 ساعة، وتُرسل قيمة ISO-8601 إلى طبقة API.
- نماذج المحتوى تدعم اختيار الصورة ورفعها مباشرة من النموذج، دون الحاجة إلى الانتقال إلى صفحة الوسائط لنسخ الرابط.

## دورة التغيير المقترحة
1. افحص الصفحة الحالية وطلبات API المرتبطة بها.
2. حافظ على أسماء مفاتيح API كما هي؛ تعريب الواجهة لا يعني تعريب أسماء الحقول المرسلة إلى الخادم.
3. اجعل الاختيارات المحدودة Dropdown، واستخدم نصًا حرًا فقط عندما تكون القيمة مفتوحة أو تقنية.
4. أظهر حالات التحميل والفراغ والخطأ والنجاح بوضوح، مع إعادة تحميل البيانات بعد التعديل.
5. وفر CRUD كاملًا فقط حيث تدعمه واجهات الخادم والصلاحيات. لا تستبدل غياب مسار API بمحاكاة محلية.
6. أضف تأكيدًا للحذف النهائي، ووضح أثر حذف السجلات المرتبطة.
7. نفّذ `flutter analyze` و`flutter test`، ثم اختبر فعليًا في الثيمين.

## معيار الواجهة
- تباعد أساسي بمضاعفات 4/8، وبطاقات متسقة وحشو واضح.
- حقول ذات تسميات صريحة، ورسائل تحقق عربية، وأزرار لمس لا تقل عن 44×44.
- تباين نصوص WCAG AA على الوضعين، وعدم الاعتماد على اللون وحده لإيصال الحالة.
- لا تضف إعدادًا يدويًا للثيم طالما أن المطلوب هو اتباع ثيم الجهاز.

## تحقق ما قبل الإصدار
- تسجيل الدخول، تجديد/انتهاء الجلسة، وحدود الصلاحيات.
- قراءة البيانات، الإضافة، التعديل، والحذف لكل مورد مدعوم.
- رفع الصور من النموذج وعرض أخطاء الخادم.
- إدخال التاريخ والوقت والتحقق من قيم ISO المرسلة.
- سلوك الواجهة عند انقطاع الشبكة، والبيانات الفارغة، والخادم غير المتاح.
